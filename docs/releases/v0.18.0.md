# AtomGit CLI v0.18.0

v0.18.0 以认证与本地状态文件的安全、可靠为主：多账号切换（`gc auth switch`）、`auth logout` 的参数与退出码修订、没有 HOME 时配置目录与状态目录的处理、凭据文件的原子写入与并发写串行化；`gc pr view` 文本模式补齐嵌套回复与评审摘要，并修复 `gc api` 分页边界与 git 凭据 helper 的输出。命令入口保持 `gc` / `gitcode` 不变。共 104 个提交（含合并）。

## ⚠ 行为变更（升级前必读）

本版本 6 项行为与 v0.17.0 不同，脚本与自动化消费方请先评估：

1. **没有 HOME 也没有 `GC_CONFIG_DIR` 时，配置不再写进当前目录**（!641、!645、!648）：在既没有 HOME（Windows 为 USERPROFILE）、也没有设置 `GC_CONFIG_DIR` 的环境里（精简容器、环境被剥离的 systemd 单元或 CI），v0.17.0 会把配置目录解析成相对路径，在当前目录下创建字面的 `~/.config/gc/`，配置和登录凭据都写在那里，也从那里读。v0.18.0 不再读写这棵目录树：
   - 读命令按"未登录/默认值"处理（`GC_TOKEN` / `GITCODE_TOKEN` 仍然生效）；`auth status` 纯文本在 stderr 多一行提示，`--json` 输出不变。
   - 写命令（登录的写入、`config set`、`repo set-default`、`lark config set` 等）报错退出 `1`，并提示设置 HOME 或 `GC_CONFIG_DIR`。
   - `auth logout` 在该环境下不再输出成功。v0.17.0 里带不带用户名都打印"✓ Cleared"并返回 `0`，现在都报错退出 `1`；不带 `--yes` 在非交互环境运行时，v0.17.0 停在确认提示并返回 `2`，现在是 `1`（环境检查先于确认提示）。本版本新增的 `auth switch` 在该环境下同样退出 `1`。

   升级后请检查：
   - 依赖"没有 HOME 也能登录或写配置"的脚本，请先设置 `HOME` 或 `GC_CONFIG_DIR`。
   - 旧版本写在某个运行目录下的 `~/.config/gc/` 不会被迁移，设置 HOME 或 `GC_CONFIG_DIR` 后需要重新登录。
   - 曾在没有 HOME 的环境里用 v0.17.0 或更早版本登录过的，请检查当时的运行目录下字面的 `~/.config/gc/`，手动删除其中的 `auth.json`（v0.18.0 的 `auth logout` 不会再清除它）；该目录若曾进入版本库、镜像或共享位置，请轮换令牌。
   - HOME 被设成相对路径或字面 `~` 的情况不在此列，仍会写到当前目录（issue 684）。
2. **`auth logout` 绑定位置参数，退出码修订**（!639，issue #658）：新增位置参数 `<username>`，等价于 `--username`。v0.17.0 里 `gc auth logout bob` 会忽略用户名，打印"✓ Cleared stored authentication for gitcode.com"并返回 `0`，实际登出的是当时的活跃账号；现在登出的是 bob，确认提示与成功消息会带上用户名（"✓ Cleared stored authentication for bob on gitcode.com"）——一直这样写的脚本，请确认这正是想要的行为。无效 hostname 的退出码由 `2` 改为 `1`（与 auth 家族统一）。目标账号未存储时，v0.17.0 打印"✓ Cleared"并返回 `0`（文件不变），现在返回 `3` 并列出可用账号（该主机没有任何已存储账号时，提示以 `no accounts are stored on this host` 结尾）。用户名为空时（例如脚本变量未赋值得到的 `-u ""`），v0.17.0 会登出活跃账号并返回 `0`，现在返回 `2`、文件不变。有一点与之前一致：不带用户名时只登出当前活跃账号，同主机其他已存储账号保留。
3. **同一台机器上，多个 gc 进程的写入串行执行**（!644，issue #672）：都是 v0.18.0 的多个 gc 进程同时登录、登出、切换账号或写配置（`config set`、`repo set-default`、`lark config set`）时，不再互相覆盖——v0.17.0 里两个进程同时登出，可能一方报成功而对应的账号仍在。配置目录里新增一个空文件 `.gc-lock`，无需清理，也不要删除；持锁的进程卡住时，其他写命令最多等待约 10 秒，然后报错退出 `1`，所以包装脚本里调用 gc 的超时要大于 10 秒。没有覆盖的情形：配置目录放在 NFS 上跨主机共享时锁不保证生效；升级期间仍在运行的旧版本进程不参与加锁。
4. **`gc api --paginate` 遇到 `null` 响应体时报错**（!629，issue #650）：v0.17.0 把它当作空页静默结束——`--slurp` 输出 `[]`、退出码 0；翻页途中出现时，此前的页照常输出、同样退出码 0。现在不论在哪一页出现，都与空响应体一致地报错、退出码 `1`。
5. **`gc pr reply --json` 的字段顺序**（!628，issue #655）：由字母序改为 `discussion_id` → `note_id` → `body`，与文档示例一致。字段集与值不变，按键取值的脚本不受影响。
6. **Linux 和 macOS 上，HOME 缺失时跳过更新状态功能**（!640，issue #671）：`GC_STATE_DIR`、`XDG_STATE_HOME`、`HOME` 均不存在时，npm 安装形态下不再在运行目录创建 `.local/state/gitcode-cli`，更新状态功能整体跳过（没有安装提示与后台更新检查）。任一变量存在的正常路径不变。Windows 的状态目录按 LOCALAPPDATA 解析，本次没有改动（issue 683）。

## 新功能

- **`gc auth switch`（多账号切换）**（!635，issue #646）：在同一配置目录、同一主机的已存储账号之间切换活动账号。`gc auth switch` 交互式列出账号并按序号选择，`gc auth switch <用户名>` 直接切换，`--json` 输出 `hostname` 与 `active_user`。切换是本地操作，不调用 API；它只改变目标主机的活动账号，不改变默认主机。v0.17.0 里换账号只能重新登录
- **`gc pr view` 文本模式显示嵌套回复与评审摘要**（!633，issue #652）：`--comments` 的评论区显示评论的嵌套回复，与 `pr comments` 的显示口径一致；详情头部（Reviewers 行之后）增加一行评审状态摘要，没有评审数据时不显示。`--json` 契约不变。文本模式会多请求一次评审状态，这次请求失败时详情照常输出，但 stderr 有提示、退出码非零——v0.17.0 没有这条退出路径，按退出码判断结果的脚本请留意

## 修复

- **`auth logout` 在没有 HOME 的环境不再报成功**（!645，issue #676）：见行为变更第 1 项
- **git 凭据 helper 的输出不再混入更新提示**（!632，issue #647）：npm 安装形态下，git 经 credential helper 调用 `gc auth git-credential` 时（clone / pull / push 每次触发），stderr 不再出现一次性更新通知与待定更新摘要，也不会写更新状态文件。普通命令的首跑提示与更新检查不变
- **`gc api --paginate` 空响应体的报错更明确**（!629，issue #650）

## 安全与可靠性

- **配置目录解析不再回退到当前目录**（!641）：见行为变更第 1 项。`config clear-cache` 在该环境下也不再读取或删除当前目录里的遗留文件
- **凭据与配置文件原子写入**（!643，issue #663）：`auth.json`、`config.json`、`lark.json` 改为先写临时文件再原子替换。由 v0.18.0 写入时，并发读取不再读到写到一半的文件；磁盘写满等写入失败时旧文件保持完好（v0.17.0 在这种情况下可能把文件截断成损坏的半截文件），命令报错退出 `1`。Windows 上目标文件正被其他程序（杀毒软件、索引服务、编辑器）占用时，会重试两次，仍失败则同样报错退出 `1`、旧文件不变。已有的只读文件（权限 0400）现在也能被替换写入，v0.17.0 会因权限不足而写入失败。进程异常中断可能遗留 `.gc-tmp-*` 临时文件，可以安全删除；正常写入时会自动清扫 60 秒以上的遗留条目。通过硬链接另存过这些文件的，链接指向的仍是旧内容
- **并发写串行化**（!644，issue #672）：见行为变更第 3 项
- **更新状态目录不再写入当前目录（Linux / macOS）**（!640，issue #671）：见行为变更第 6 项

## 文档

- **`gc api` 与 gh 的行为差异说明**（!627，issue #651）：docs/COMMANDS.md 的 api 小节新增从 gh 迁移时的差异（`$ENV` 不加载环境变量、GET 下 `-f` 不转查询参数、超大整数精度、`halt` 语义），环境变量表新增 `GC_CONFIG_DIR`
- **AI-GUIDE：仓库协作者邀请的自动化断点**（!638）：`PUT collaborators` 可用，但邀请的列出与接受没有对应端点，私有仓库在被邀请方接受前读取返回 403——需要有人在 gitcode.com 网页上接受邀请，自动化应在此处暂停。相关 issue 656 保持 open，作为平台端点跟踪项
- **认证文档同步**（随 !635、!639、!641、!643、!644、!645、!648）：docs/AUTH.md 与 docs/COMMANDS.md 补充了多账号切换的语义与退出码、HOME 缺失时的行为、`.gc-lock` 与 `.gc-tmp-*` 的说明、`auth logout` 的退出码，以及"不带用户名的登出只清除活跃账号"

## 内部加固

- **规范**：帮助文本采用内联还是包级变量的取舍标准（!637，issue #654）
- **API 层**：讨论 ID 路径段统一转义；回复类型更名，区分两种语义（!630，issue #653）
- **git 凭据的单次读取**（!634，issue #649）：`auth git-credential` 组装用户名与访问令牌，由分两次读取 `auth.json` 改为单次读取的一致快照，并发登录或切换账号落在两次读取之间时不再可能输出跨账号的错配对。正常与未命中场景的输出、退出码不变
- **回归测试**：默认回归集新增 `auth git-credential` 的静默退出检查、`gc api` 新 flag 的冒烟用例，以及两个进程并发登出的检查（!631 issue #648，!644）
- **测试**：修复 Windows 下测试句柄未关闭导致的临时目录清理失败（!636，issue #657）

## 推荐升级方式

### 短命令快速升级

可信的个人本地环境可优先使用短命令（推荐坐标）：

```bash
npx -y atomgit-cli@latest install
gitcode version
gitcode doctor install
```

等价坐标：`npx -y @gitcode-cli/cli@latest install`（旧坐标长期可用，无需迁移）。

短命令会继承当前目录和用户的 npm 配置。请仅在确认这些配置（包括 `.npmrc`）可信时使用。

CI、审计、未知项目目录或自定义 npm registry 环境，使用安全强化命令：

```bash
npx --yes --ignore-scripts --registry=https://registry.npmjs.org atomgit-cli@latest install
gitcode version
```

（scoped 坐标加固形式：`npx --yes --ignore-scripts --registry=https://registry.npmjs.org --@gitcode-cli:registry=https://registry.npmjs.org @gitcode-cli/cli@latest install`）

### 锁定版本安装

```bash
npx --yes --ignore-scripts --registry=https://registry.npmjs.org atomgit-cli@0.18.0 install
gitcode version
```

（scoped 坐标锁定形式：`npx --yes --ignore-scripts --registry=https://registry.npmjs.org --@gitcode-cli:registry=https://registry.npmjs.org @gitcode-cli/cli@0.18.0 install`）

### 其他渠道

- **npm 全局（经典）/ npm-bootstrap**：`gc update`，或上面的 npx 命令
- **pnpm 全局**：`pnpm add -g atomgit-cli@latest`（`gc update` 会给出该指引）
- **Homebrew**：`brew update && brew upgrade gc`
- **pip / pipx**：`pip install -U gitcode-cli` / 在对应环境升级
- **deb / rpm**：通过系统包管理器升级
