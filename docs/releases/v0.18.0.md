# AtomGit CLI v0.18.0

v0.18.0 以认证与本地状态文件的安全、可靠为主：多账号切换（`gc auth switch`）、`auth logout` 的参数与退出码调整、没有 HOME 时配置目录与状态目录的处理、凭据文件的原子写入，以及多个 gc 进程并发写入时排队执行；`gc pr view` 文本模式补齐嵌套回复与评审摘要，并修复 `gc api` 分页时对 `null` 响应体的处理，以及 git 凭据 helper 的输出里混入更新提示的问题。命令入口保持 `gc` / `gitcode` 不变。共 104 个提交（含合并）。

## ⚠ 行为变更（升级前必读）

本版本 8 项行为与 v0.17.0 不同，脚本与自动化消费方请先评估。关于 HOME 的一项后果最重，但只影响没有 HOME 的环境，单独说明；其余 7 项列在后面，建议都过一遍。

### 没有 HOME 也没有 GC_CONFIG_DIR 时，配置不再写进当前目录

对应 !641、!645、!648。

**谁受影响**：只有在既没有 HOME（Windows 为 USERPROFILE）、也没有设置 `GC_CONFIG_DIR` 的环境里才会遇到，常见的是精简容器、环境被清空的 systemd 单元或 CI。有 HOME 或 `GC_CONFIG_DIR` 的环境不受影响；例外是 HOME 被设成相对路径或字面 `~`，或者 `GC_CONFIG_DIR` 被设成相对路径，见下文"升级后"。

**改了什么**：v0.17.0 在这种环境下会在当前目录里创建一个名字就叫 `~` 的目录（`./~/.config/gc/`），配置和登录凭据都写在那里，也从那里读。v0.18.0 不再读写这个目录：

- 读命令按"未登录、使用默认值"处理，`GC_TOKEN` / `GITCODE_TOKEN` 仍然生效。`auth status` 未登录时，纯文本输出会在 stderr 多一行环境提示（issue 677）；`--json` 不追加提示，输出的 JSON 与 v0.17.0 相同。脚本无法凭 `--json` 区分"配置目录不可解析"与"未登录"；运行目录里留有旧凭据时，`logged_in` 会从 `true` 变成 `false`。
- 写命令（`config set`、`repo set-default`、`lark config set` 等）报错退出 `1`，并提示设置 HOME 或 `GC_CONFIG_DIR`。`auth login` 不会先检查环境：令牌无效时仍先报令牌校验失败；令牌有效时才会走到写入这一步，这时才报上面这个错（见 issue 680）。
- `auth logout` 不再输出成功。v0.17.0 不论带不带用户名都打印"✓ Cleared"并返回 `0`，现在都报错退出 `1`（用户名为空或冲突时仍返回用法错误 `2`）。不带 `--yes` 在非交互环境下运行时，v0.17.0 停在确认提示并返回 `2`，现在是 `1`，因为 v0.18.0 先检查环境、后进入确认提示。本版本新增的 `auth switch` 在该环境下同样退出 `1`。

**升级前**：依赖"没有 HOME 也能登录或写配置"的脚本，请先设置 `HOME` 或 `GC_CONFIG_DIR`。

**升级后**：

- 旧版本留在运行目录里的 `./~/.config/gc/` 不会被迁移，默认也读不到。设置 HOME 或 `GC_CONFIG_DIR` 后需要重新登录；想保留原来的登录，可以把其中的 `auth.json` 移到新的配置目录。
- 剩下的 `./~/.config/gc/` 目录请整个删除，尤其是没有移走的 `auth.json`（v0.18.0 的 `auth logout` 不会再清除它）；这个目录如果曾进入版本库、镜像或共享位置，请轮换令牌。如果当时设置的是 `HOME` 为字面 `~` 之类的值，这个目录在 v0.18.0 里仍在使用，不要删除，见下一条。
- HOME 或 `GC_CONFIG_DIR` 被设成相对路径，或者 HOME 被设成字面 `~` 的情况不在本次修复范围内，仍会写到当前目录（issue 684）。

### 其余 7 项

1. **`gc auth logout <用户名>` 现在登出的是这个用户**（!639，issue 658）。新增位置参数 `<用户名>`，等价于 `--username`。v0.17.0 会忽略它：`gc auth logout bob` 打印"✓ Cleared stored authentication for gitcode.com"并返回 `0`，实际登出的是当时的活跃账号。现在登出的是 bob，确认提示与成功消息会带上用户名（"✓ Cleared stored authentication for bob on gitcode.com"）。一直这样写的脚本，请确认这正是想要的行为。按退出码判断登出结果的脚本，请对照下一项检查。
2. **`auth logout` 的退出码有变化**（!639，issue 658）。目标账号未存储时，v0.17.0 打印"✓ Cleared"并返回 `0`（文件不变），现在返回 `3` 并列出可用账号；该主机没有任何已存储账号时，提示以 `no accounts are stored on this host` 结尾。用户名为空时（例如脚本变量未赋值得到的 `-u ""` 或空的位置参数），v0.17.0 会登出活跃账号并返回 `0`，现在返回 `2`、文件不变。用户名同时用位置参数和 `--username` 给出且不一致，或位置参数多于一个时返回 `2`（v0.17.0 会忽略位置参数）。无效 hostname 的退出码由 `2` 改为 `1`，与其他 auth 子命令一致。有一点没变：不带用户名时只登出当前活跃账号，同主机其他已存储账号保留；该主机没有任何已存储账号时，仍打印"✓ Cleared"并返回 `0`。
3. **同一台机器上，多个 gc 进程同时写入时排队执行**（!644，issue 672）。有多个 v0.18.0 的 gc 进程同时登录、登出、切换账号或写配置（`config set`、`repo set-default`、`lark config set`）时，写入不再互相覆盖。v0.17.0 里两个进程同时登出，可能其中一个打印了成功消息，它要登出的账号却还留在文件里；并发写入时另一个进程读到的，还可能是写到一半的文件（这一点由"安全与可靠性"里的原子写入解决）。配置目录里新增一个空文件 `.gc-lock`，无需清理，也不要删除。持锁的进程卡住时，其他写命令最多等待约 10 秒，然后报错退出 `1`，所以包装脚本里调用 gc 的超时要明显大于 10 秒，否则等待中的 gc 会被外层超时直接杀掉，看不到任何报错。没有覆盖的情形：配置目录放在 NFS 上跨主机共享时，锁不保证生效；升级时仍在运行的旧版本进程不会加锁，和它并发写入仍可能互相覆盖。
4. **`gc api --paginate` 遇到 `null` 响应体时报错**（!629，issue 650）。v0.17.0 把它当作空页静默结束：`--slurp` 输出 `[]`、退出码 `0`；翻页途中出现时，此前的页照常输出、同样退出码 `0`。现在不论出现在哪一页，都按空响应体的同一格式报错，退出码 `1`；不带 `--slurp` 时，报错前已经输出的页会留在输出里，`--slurp` 下则不输出已合并的页。
5. **`gc pr reply --json` 的字段顺序**（!628，issue 655）。由字母序改为 `discussion_id`、`note_id`、`body`，与文档示例一致。字段集与值不变，按键取值的脚本不受影响。
6. **Linux 和 macOS 上，`HOME`、`XDG_STATE_HOME`、`GC_STATE_DIR` 均缺失时跳过更新状态功能**（!640，issue 671）。通过 npm bootstrap（`npx … install`）安装时，v0.17.0 会在运行目录里创建 `.local/state/gitcode-cli`（没有禁用更新检查时，还会显示首次运行的更新提示）；v0.18.0 不再创建这个目录，更新状态功能整体跳过（没有安装提示，也没有后台更新检查）。旧版本留下的这个目录只存放更新状态，没有凭据，可以直接删除。这三个变量中任何一个设置了绝对路径时，行为不变。Windows 的状态目录按 LOCALAPPDATA 解析，本次没有改动（issue 683）。
7. **`gc pr view` 文本模式多一种非零退出的情况**（!633，issue 652）。文本模式现在会多请求一次评审状态；这次请求失败时详情照常输出，但 stderr 有提示、退出码非零。v0.17.0 不发这次请求，没有这条退出路径；获取 PR 统计数据失败、获取评论失败时返回非零的规则不变。`--json` 模式不发起这次请求，不受影响。按退出码判断 `pr view` 结果的脚本请留意。

## 新功能

- **`gc auth switch`（多账号切换）**（!635，issue 646）。在同一配置目录、同一主机的已存储账号之间切换活动账号：`gc auth switch` 交互式列出账号并按序号选择，`gc auth switch <用户名>` 直接切换，`--json` 输出 `hostname` 与 `active_user`。切换是本地操作，不调用 API；它只改变目标主机的活动账号，不改变默认主机。默认主机上已设置 `GC_TOKEN` / `GITCODE_TOKEN` 时，业务命令仍使用环境变量里的 token，切换不影响它们（命令会在 stderr 输出一行提示，`--json` 模式不输出）；git 经 credential helper 取凭据时用的是切换后的账号。非交互环境下不带用户名返回 `2`；账号未存储、或主机没有任何已存储账号时返回 `3`。v0.17.0 里要换账号，只能用不同的 `GC_CONFIG_DIR`，或者重新登录。
- **`gc pr view` 文本模式显示嵌套回复与评审摘要**（!633，issue 652）。`--comments` 的评论区显示评论的嵌套回复，显示方式与 `pr comments` 相同；详情头部（Reviewers 行之后）增加一行评审状态摘要，没有评审数据时不显示。`--json` 契约不变。退出码的变化见"其余 7 项"里关于 `gc pr view` 的一条。

## 修复

- **git 凭据 helper 的输出不再混入更新提示**（!632，issue 647）。通过 npm bootstrap（`npx … install`）安装时，git 经 credential helper 调用 `gc auth git-credential`（clone、pull、push 每次都会触发），stderr 不再出现首次运行的更新提示和待显示的更新摘要，也不会写更新状态文件。普通命令的首次运行提示与更新检查不变。

## 安全与可靠性

- **`config clear-cache` 不再动当前目录里的遗留文件**（!641）。在既没有 HOME 也没有 `GC_CONFIG_DIR` 的环境下，v0.17.0 会读取并删除当前目录里 `./~/.config/gc/cache/` 下的文件；现在输出 `No cache to clear.`，文件保持不动。
- **凭据与配置文件原子写入**（!643，issue 663）。`auth.json`、`config.json`、`lark.json` 改为先写临时文件再原子替换。由 v0.18.0 写入时，并发读取不再读到写到一半的文件；磁盘写满等写入失败时旧文件保持完好（v0.17.0 在这种情况下可能把文件截断成损坏的半截文件），命令报错退出 `1`。Windows 上目标文件正被其他程序（杀毒软件、索引服务、编辑器）占用时，会紧接着重试两次，仍失败则同样报错退出 `1`、旧文件不变（v0.17.0 是原地写入，通常不会因此失败）。Linux 和 macOS 上，已有的只读文件（权限 0400）现在也能被替换写入，v0.17.0 会因权限不足而写入失败；替换后的新文件权限为 `0600`。进程异常中断可能遗留 `.gc-tmp-*` 临时文件（内容是 `auth.json`、`config.json` 或 `lark.json` 的完整副本，权限 0600），可以安全删除；正常写入时会自动删除 60 秒前留下的这类文件。用硬链接备份过这些文件的，备份里留的是旧内容，不会随文件更新。

## 文档

- **`gc api` 与 gh 的行为差异说明**（!627，issue 651）。docs/COMMANDS.md 的 api 小节新增从 gh 迁移时的差异（`$ENV` 不加载环境变量、GET 下 `-f` 不转查询参数、超大整数精度、`halt` 语义），环境变量表新增 `GC_CONFIG_DIR`。
- **AI-GUIDE：仓库协作者邀请需要人工接受，自动化流程要在这里暂停**（!638）。`PUT collaborators` 可以用，但没有 API 可以列出或接受邀请；私有仓库在被邀请的一方接受之前读取会返回 403，需要有人在 gitcode.com 网页上接受邀请。相关 issue 656 保持 open，用来跟踪平台补充这些端点的进展。
- **认证文档**（随各功能的 PR 同步）。多账号切换的用法、HOME 缺失时的行为和 `auth logout` 的退出码写在 docs/COMMANDS.md 和 docs/AUTH.md；`auth switch` 的退出码只写在 docs/COMMANDS.md；`.gc-lock` 与 `.gc-tmp-*` 的说明在 docs/AUTH.md。

## 内部加固

- **规范**：帮助文本采用内联还是包级变量的取舍标准（!637，issue 654）。
- **API 层**：讨论 ID 路径段统一转义，回复类型更名（!630，issue 653）。
- **git 凭据的单次读取**（!634，issue 649）。v0.17.0 分两次从 `auth.json` 读取用户名和令牌，如果另一个进程恰好在这两次读取之间登录了另一个账号，可能把一个账号的用户名和另一个账号的令牌拼在一起输出。现在一次读取整个文件。正常情况和凭据缺失时的输出、退出码不变。
- **回归测试**：默认回归集新增 `auth git-credential` 的静默退出检查、`gc api` 新 flag 的冒烟用例，以及两个进程并发登出的检查（!631、!644）。
- **测试**：修复 Windows 下测试句柄未关闭导致的临时目录清理失败（!636，issue 657）。

## 推荐升级方式

### 短命令快速升级

可信的个人本地环境可优先使用短命令（推荐坐标）：

```bash
npx -y atomgit-cli@latest install
gitcode version
gitcode doctor install
```

等价坐标：`npx -y @gitcode-cli/cli@latest install`（旧坐标长期可用，无需迁移）。

短命令会继承当前目录和用户的 npm 配置。请仅在确认这些配置（包括 `.npmrc`）可信时使用。

CI、审计、未知项目目录或自定义 npm registry 环境，使用安全强化命令：

```bash
npx --yes --ignore-scripts --registry=https://registry.npmjs.org atomgit-cli@latest install
gitcode version
```

（scoped 坐标加固形式：`npx --yes --ignore-scripts --registry=https://registry.npmjs.org --@gitcode-cli:registry=https://registry.npmjs.org @gitcode-cli/cli@latest install`）

### 锁定版本安装

```bash
npx --yes --ignore-scripts --registry=https://registry.npmjs.org atomgit-cli@0.18.0 install
gitcode version
```

（scoped 坐标锁定形式：`npx --yes --ignore-scripts --registry=https://registry.npmjs.org --@gitcode-cli:registry=https://registry.npmjs.org @gitcode-cli/cli@0.18.0 install`）

### 其他渠道

- **npm 全局（经典）/ npm-bootstrap**：`gitcode update`，或上面的 npx 命令
- **pnpm 全局**：`pnpm add -g atomgit-cli@latest`（`gitcode update` 会给出该指引）
- **Homebrew**：`brew update && brew upgrade gc`
- **pip / pipx**：`pip install -U gitcode-cli` / 在对应环境升级
- **deb / rpm**：需要手动升级。没有配置 apt / dnf 软件源时，系统的包管理器不会自动发现新版本；请下载对应架构的安装包后安装，地址如下：

deb（AMD64；ARM64 设备把文件名换成 `gc_0.18.0_arm64.deb`）：

```bash
wget https://gitcode.com/atomgit-cli/cli/releases/download/v0.18.0/gc_0.18.0_amd64.deb
sudo dpkg -i gc_0.18.0_amd64.deb
```

rpm（x86_64；用 `-U` 升级，未安装时等同于安装。aarch64 设备把文件名换成 `gc-0.18.0-1.aarch64.rpm`）：

```bash
wget https://gitcode.com/atomgit-cli/cli/releases/download/v0.18.0/gc-0.18.0-1.x86_64.rpm
sudo rpm -U gc-0.18.0-1.x86_64.rpm
```
