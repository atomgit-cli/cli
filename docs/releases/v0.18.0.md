# AtomGit CLI v0.18.0

v0.18.0 以认证与本地状态文件的安全、可靠为主：多账号切换（`gc auth switch`）、`auth logout` 参数与退出码修订、配置目录与状态目录在异常环境下的处理、凭据文件的原子写入与并发写串行化；`gc pr view` 文本模式补齐嵌套回复与评审摘要，并修复 `gc api` 分页边界与 git 凭据 helper 的输出纯净度。命令入口保持 `gc` / `gitcode` 不变。共 104 个提交（含合并）。

## ⚠ 行为变更（升级前必读）

本版本 6 项行为与之前的发布语义不同，脚本与自动化消费方请先评估：

1. **配置目录不可解析时，写命令报错而不是写进当前目录**（!641、!645、!648）：在既没有 HOME（Windows 为 USERPROFILE）、也没有设置 `GC_CONFIG_DIR` 的环境里（精简容器、环境被剥离的 systemd 单元或 CI），此前 gc 会把配置目录解析成相对路径，在当前目录下创建字面的 `~/.config/gc/` 并把配置与登录凭据写进去。现在读命令读不到已存储的登录态，按"未登录/默认值"处理（`GC_TOKEN` / `GITCODE_TOKEN` 仍然生效；`auth status` 纯文本多一行提示，`--json` 输出不变）；写命令（登录的写入、`config set`、`repo set-default`、`lark config set` 等）报错退出 `1`，并提示设置 HOME 或 `GC_CONFIG_DIR`。同一环境下 `auth logout` 不再输出成功：不带用户名时退出码由 `0` 改为 `1`，带用户名的 `auth logout` 与 `auth switch` 由 `3` 改为 `1`，且环境检查先于确认提示。依赖"无 HOME 也能登录或写配置"的脚本，请先设置 `HOME` 或 `GC_CONFIG_DIR`。
2. **`auth logout` 绑定位置参数，退出码修订**（!639，issue #658）：新增位置参数 `<username>`，等价于 `--username`。此前 `gc auth logout bob` 的用户名被静默忽略，实际登出的是活跃账号；现在登出的是 bob——一直这样写的脚本，请确认这正是想要的行为。无效 hostname 的退出码由 `2` 改为 `1`（与 auth 家族统一）；目标账号未存储返回 `3` 并列出可用账号；用户名为空返回 `2`。不带用户名时只登出当前活跃账号，同主机其他已存储账号保留。
3. **多个 gc 进程的写入串行执行**（!644，issue #672）：并发登录、登出、切换账号不再互相覆盖（此前两个进程同时登出，可能一方报成功而对应的账号仍在）。配置目录里新增一个空文件 `.gc-lock`，无需清理，也不要删除；持锁的进程卡住时，其他写命令最多等待约 10 秒，然后报错退出 `1`。
4. **`gc api --paginate` 遇到 `null` 响应体时报错**（!629，issue #650）：此前被当作空页静默结束（`--slurp` 输出 `[]`、退出码 0），现在与空响应体一致地报错、退出码 `1`。
5. **`gc pr reply --json` 的字段顺序**（!628，issue #655）：由字母序改为 `discussion_id` → `note_id` → `body`，与文档示例一致。字段集与值不变，按键取值的脚本不受影响。
6. **HOME 缺失时跳过更新状态功能**（!640，issue #671）：`GC_STATE_DIR`、`XDG_STATE_HOME`、`HOME` 均不存在时，不再在运行目录创建 `.local/state/gitcode-cli`，更新状态功能整体跳过（没有安装提示与后台更新检查）。任一变量存在的正常路径不变。

## 新功能

- **`gc auth switch`（多账号切换）**（!635，issue #646）：在同一配置目录、同一主机的已存储账号之间切换活动账号。`gc auth switch` 交互式列出账号并按序号选择，`gc auth switch <用户名>` 直接切换，`--json` 输出 `hostname` 与 `active_user`。切换是本地操作，不调用 API；它只改变目标主机的活动账号，不改变默认主机。此前换账号只能重新登录
- **`gc pr view` 文本模式显示嵌套回复与评审摘要**（!633，issue #652）：评论的嵌套回复与 `pr comments` 的显示口径一致，详情末尾增加一行评审状态摘要。`--json` 契约不变

## 修复

- **`auth logout` 不再无据报成功**（!645，issue #676）：见行为变更第 1 项。另外，账号列表为空时不再输出悬空的 `available: `，改为 `no accounts are stored on this host`
- **git 凭据 helper 的输出不再混入更新提示**（!632，issue #647）：git 经 credential helper 调用 `gc auth git-credential` 时（clone / pull / push 每次触发），stderr 不再出现一次性更新通知与待定更新摘要。普通命令的首跑提示与更新检查不变
- **git 凭据的用户名与令牌改为单次读取**（!634，issue #649）：此前分两次读取 `auth.json`，并发登录或切换账号落在两次读取之间时，可能输出跨账号的错配对；现在取自同一次读取的一致快照。正常与未命中场景的输出、退出码不变
- **`gc api --paginate` 空响应体的报错更明确**（!629，issue #650）

## 安全与可靠性

- **配置目录解析不再回退到当前目录**（!641）：见行为变更第 1 项。`config clear-cache` 在该环境下也不再读取或删除当前目录里的遗留文件
- **凭据与配置文件原子写入**（!643，issue #663）：`auth.json`、`config.json`、`lark.json` 改为先写临时文件再原子替换。并发读取不再可能读到写到一半的文件；磁盘写满等写入失败时旧文件保持完好（此前可能被截断成损坏的半截文件）。进程异常中断可能遗留 `.gc-tmp-*` 临时文件，可以安全删除；正常写入时会自动清扫 60 秒以上的遗留条目
- **并发写串行化**（!644，issue #672）：见行为变更第 3 项
- **更新状态目录不再写入当前目录**（!640，issue #671）：见行为变更第 6 项

## 文档

- **`gc api` 与 gh 的行为差异说明**（!627，issue #651）：docs/COMMANDS.md 的 api 小节新增从 gh 迁移时的差异（`$ENV` 不加载环境变量、GET 下 `-f` 不转查询参数、超大整数精度、`halt` 语义），环境变量表新增 `GC_CONFIG_DIR`
- **AI-GUIDE：仓库协作者邀请的自动化断点**（!638）：`PUT collaborators` 可用，但邀请的列出与接受没有对应端点，私有仓库在被邀请方接受前读取返回 403——需要有人在 gitcode.com 网页上接受邀请，自动化应在此处暂停。相关 issue 656 保持 open，作为平台端点跟踪项
- **认证文档同步**（随 !641、!645、!648）：docs/AUTH.md 与 docs/COMMANDS.md 补充了 HOME 缺失时的行为、`.gc-lock` 的说明、`auth logout` 与 `auth switch` 的退出码，以及"不带用户名的登出只清除活跃账号"

## 推荐升级方式

### 短命令快速升级

可信的个人本地环境可优先使用短命令（推荐坐标）：

```bash
npx -y atomgit-cli@latest install
gitcode version
gitcode doctor install
```

等价坐标：`npx -y @gitcode-cli/cli@latest install`（旧坐标长期可用，无需迁移）。

短命令会继承当前目录和用户的 npm 配置。请仅在确认这些配置（包括 `.npmrc`）可信时使用。

CI、审计、未知项目目录或自定义 npm registry 环境，使用安全强化命令：

```bash
npx --yes --ignore-scripts --registry=https://registry.npmjs.org atomgit-cli@latest install
gitcode version
```

（scoped 坐标加固形式：`npx --yes --ignore-scripts --registry=https://registry.npmjs.org --@gitcode-cli:registry=https://registry.npmjs.org @gitcode-cli/cli@latest install`）

### 锁定版本安装

```bash
npx --yes --ignore-scripts --registry=https://registry.npmjs.org atomgit-cli@0.18.0 install
gitcode version
```

（scoped 坐标锁定形式：`npx --yes --ignore-scripts --registry=https://registry.npmjs.org --@gitcode-cli:registry=https://registry.npmjs.org @gitcode-cli/cli@0.18.0 install`）

### 其他渠道

- **npm 全局（经典）/ npm-bootstrap**：`gc update`，或上面的 npx 命令
- **pnpm 全局**：`pnpm add -g atomgit-cli@latest`（`gc update` 会给出该指引）
- **Homebrew**：`brew update && brew upgrade gc`
- **pip / pipx**：`pip install -U gitcode-cli` / 在对应环境升级
- **deb / rpm**：通过系统包管理器升级
