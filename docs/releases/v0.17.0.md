# AtomGit CLI v0.17.0

v0.17.0 是以 Git 工作流与 API 消费能力为主的版本：git HTTPS 操作免交互凭据落地（`auth setup-git` 写入的 credential helper 交付）、`gc api` 补齐轮询友好四能力（响应头/翻页/jq 过滤/表单字段）、PR 评审状态读取与讨论回复可见；配套一机多账号隔离文档（`GC_CONFIG_DIR`）、认证输出边界修正与双端 CI 工具链统一。命令入口保持 `gc` / `gitcode` 不变。共 44 个提交（含合并）。

## ⚠ 行为变更（升级前必读）

本版本 2 项行为与之前的发布语义不同，脚本与自动化消费方请先评估：

1. **`gc api` 对 HTTP 304 一律非零退出**：此前条件请求命中 304（空响应体）被静默当作成功 exit 0——有误导；现在统一以非零退出结束（错误消息含 304），配 `--include` 时先输出响应头再报错。消费方可据此把"非零退出 + 304"判定为"资源未变化"。当前 GitCode v5 多数端点不返回 ETag，该路径在无 ETag 的端点不可达。
2. **`auth logout` 的默认主机环境变量提示迁移到 stderr**（!605）：`GC_TOKEN` / `GITCODE_TOKEN` 已设置时登出，提示（含按平台的当前终端清理命令）现写入 stderr，stdout 保持纯结果输出——与 agent-friendly 输出边界一致。

## 新功能

- **`gc auth git-credential`（git credential helper 协议）**（!621，issue #641）：`auth setup-git` 写入的 helper 条目至此交付填充能力——git 的 HTTPS clone/pull/push 免交互使用已保存凭据（username=登录名、password=访问令牌）；未命中时静默非零退出（git 继续询问后续 helper）；凭据值只出现在 stdout 协议输出；`GC_CONFIG_DIR` 隔离语义完全确定（空目录或空字符串值均不回落默认目录、环境 token 不适用）
- **`gc api` 五项能力**（!622，issue #642）：`--include`（响应状态行+响应头随体输出，gh 兼容格式）、`--paginate`（跟随 page 参数自动翻页至空页，per_page 缺省注入，100 页安全上限）、`--slurp`（分页合并为单一 JSON 数组）、`--jq`（gojq 完整 jq 语法过滤输出，字符串原文/紧凑 JSON 行）、`-f, --field`（key=value 字段构造 JSON 请求体，免临时文件）；各 flag 与既有 `-H/-X/--input` 组合关系与退出码契约见 docs/COMMANDS.md
- **`gc pr reviews`（PR 评审状态读取）**（!625，issue #645）：v5 无专门 reviews 端点，评审状态内嵌于 PR 详情——本命令输出三组状态：评审人（`accept_status`：approved/rejected/pending）、测试人（accepted/pending）、审核人；文本模式含状态着色与 code owner 标注，`--json` 输出原始字段形态，无评审数据时返回空列表
- **`gc actions run watch --wait`**（!618）：脚本可等待运行结束再继续（退出码承载结论），JSON 输出不受影响

## 修复

- **PR 讨论回复可读回**（!624，issue #644）：`gc pr reply` 发布的回复此前在 CLI 侧"只写不读"——`PRComment` 结构体缺 `Reply` 字段导致列表嵌套的回复数组在解析层被丢弃，且 `noteId` JSON 标签错误使回复 id（`note_id`）从未显示。现在 `gc pr comments` 文本与 `--json` 均包含嵌套回复（回复 id 可用于单条读取/删除），`gc pr reply` 输出 Comment ID 并支持 `--json` 返回 note_id（幂等查重与回读句柄）
- **auth logout 环境变量提示与主机处理加固**（!605，Codex）：提示迁移 stderr 并按平台（Unix `unset` / PowerShell `Remove-Item Env:`）输出当前终端清理命令；共享 `ConfirmYesNo` 组件抽取（login 复用）
- **npm dist-tag 传播重试窗口**（!617，issue #636）：发布后三坐标 dist-tag 校验重试窗口加宽至覆盖 registry 实测传播延迟（约 6 分钟），查询失败计入重试而非中断

## 文档

- **一机多账号（GC_CONFIG_DIR 隔离）**（!623，issue #643）：`gc auth --help` 与 `gc config --help` 增加环境变量说明；docs/AUTH.md 新增 wrapper 双账号示例（空目录=未登录、无回落）与 git 侧使用前提（运行 git 的环境需导出同一 `GC_CONFIG_DIR`）

## 推荐升级方式

### 短命令快速升级

可信的个人本地环境可优先使用短命令（推荐坐标）：

```bash
npx -y atomgit-cli@latest install
gitcode version
gitcode doctor install
```

等价坐标：`npx -y @gitcode-cli/cli@latest install`（旧坐标长期可用，无需迁移）。

短命令会继承当前目录和用户的 npm 配置。请仅在确认这些配置（包括 `.npmrc`）可信时使用。

CI、审计、未知项目目录或自定义 npm registry 环境，使用安全强化命令：

```bash
npx --yes --ignore-scripts --registry=https://registry.npmjs.org atomgit-cli@latest install
gitcode version
```

（scoped 坐标加固形式：`npx --yes --ignore-scripts --registry=https://registry.npmjs.org --@gitcode-cli:registry=https://registry.npmjs.org @gitcode-cli/cli@latest install`）

### 锁定版本安装

```bash
npx --yes --ignore-scripts --registry=https://registry.npmjs.org atomgit-cli@0.17.0 install
gitcode version
```

（scoped 坐标锁定形式：`npx --yes --ignore-scripts --registry=https://registry.npmjs.org --@gitcode-cli:registry=https://registry.npmjs.org @gitcode-cli/cli@0.17.0 install`）

### 其他渠道

- **npm 全局（经典）/ npm-bootstrap**：`gc update`，或上面的 npx 命令
- **pnpm 全局**：`pnpm add -g atomgit-cli@latest`（`gc update` 会给出该指引）
- **Homebrew**：`brew update && brew upgrade gc`
- **pip / pipx**：`pip install -U gitcode-cli` / 在对应环境升级
- **deb / rpm**：通过系统包管理器升级
