# AtomGit CLI v0.16.0

v0.16.0 是以认证正确性与仓库设置修复为主的版本：裸 `gc auth login` 的主机解析与业务命令对齐（消除 GC_HOST 组合下的"登录了却不生效"与警告归因偏差）、`repo pr-settings` 嵌套响应读取修复并补齐 `--close-issue-on-merge`、非真实终端的确认门前置拒绝、auth 环境变量覆盖指引体系化；配套大规模内部加固——双端 CI 契约测试体系、Python 单测双端接入、三批死代码清理（删除 834 行）。命令入口保持 `gc` / `gitcode` 不变。共 64 个提交。

## ⚠ 行为变更（升级前必读）

本版本 1 项行为与之前的发布语义不同，脚本与自动化消费方请先评估（未设置 `GC_HOST` 且无历史自定义主机的多数用户不受影响，行为不变）：

1. **裸 `gc auth login`（不带 `--hostname`）的主机解析跟随业务命令**：按 `GC_HOST` > 上次登录主机 > `gitcode.com` 解析目标（与 `AuthenticatedClient` 同一逻辑）。设置 `GC_HOST` 后裸登录即为该主机建立本地认证（此前固定登录 `gitcode.com`，在自定义主机场景下登录实际不生效）。显式 `--hostname` 不变；`--web` 流程仍固定 `gitcode.com`。交互模式下登录自定义主机时，粘贴 token 前会显示 `Target host: <host>` 行，便于在凭证提交前确认目标。

## 新功能

- **`repo pr-settings update --close-issue-on-merge[=false]`**（!608）：补齐 `close_issue_when_mr_merged` 的命令面（此前只能手工发 PUT）；`--close-issue-on-merge=false` 显式关闭
- **issue 模板（双平台渲染）**（!601）：Bug 报告 / 功能建议模板在 GitCode 与 GitHub 网页端可用——四段式结构（背景与证据/改动建议/验收标准/影响范围）、敏感信息脱敏提示、`gc issue create --security-hole` 私密通道指引
- **dev-setup PATH 缺失警告**（!615，贡献者面）
- **CONTRIBUTING 网络前置说明**（!596，贡献者面）：模块代理与网络可达性排查指引：managed 工具目录不在 PATH 时，结尾输出"钩子将失败"警告与可粘贴的 profile 示例；`--check` 计入 gap 非零退出；`go mod download` 失败附 GOPROXY 检查指引与公共镜像示例

## 修复

- **`repo pr-settings view` 嵌套响应读取**（!608）：平台把多数门禁字段包在 `merge_request_setting` 对象内，旧扁平解码使 `can_reopen`、`close_issue_when_mr_merged` 等真实为 `true` 的字段一律显示 `false`；现按嵌套、扁平、混合及 null 包裹四种形态正确解码
- **非真实终端的确认门**（!613）：stdin 重定向自 `/dev/null`（或 Windows `NUL`）时不再误判为可交互——确认门直接输出非交互错误并要求 `--yes`（此前先打印 prompt 块再靠空输入兜底；最终行为相同，输出更干净、不再依赖兜底路径）
- **auth 环境变量覆盖指引体系**（!593、!597）：环境变量 token 与本地登录并存时，`auth login` 在保存前经确认门（默认不保存、防粘贴丢输入）、`auth status` 失败路径输出按平台适配的根治指引（unset / 配置文件停用 / 新终端验证，仅输出命令不自动修改）

- **AI 协作记录校验**（!603）：`validate-ai-record.py` record 模式接入 CI——验证记录/自检记录按模板强制校验，模板原样提交会被拒绝

## 推荐升级方式

### 短命令快速升级

可信的个人本地环境可优先使用短命令（推荐坐标）：

```bash
npx -y atomgit-cli@latest install
gitcode version
gitcode doctor install
```

等价坐标：`npx -y @gitcode-cli/cli@latest install`（旧坐标长期可用，无需迁移）。

短命令会继承当前目录和用户的 npm 配置。请仅在确认这些配置（包括 `.npmrc`）可信时使用。

CI、审计、未知项目目录或自定义 npm registry 环境，使用安全强化命令：

```bash
npx --yes --ignore-scripts --registry=https://registry.npmjs.org atomgit-cli@latest install
gitcode version
```

（scoped 坐标加固形式：`npx --yes --ignore-scripts --registry=https://registry.npmjs.org --@gitcode-cli:registry=https://registry.npmjs.org @gitcode-cli/cli@latest install`）

### 锁定版本安装

```bash
npx --yes --ignore-scripts --registry=https://registry.npmjs.org atomgit-cli@0.16.0 install
gitcode version
```

（scoped 坐标锁定形式：`npx --yes --ignore-scripts --registry=https://registry.npmjs.org --@gitcode-cli:registry=https://registry.npmjs.org @gitcode-cli/cli@0.16.0 install`）

### 其他渠道

- **npm 全局（经典）/ npm-bootstrap**：`gc update`，或上面的 npx 命令
- **pnpm 全局**：`pnpm add -g atomgit-cli@latest`（`gc update` 会给出该指引）
- **Homebrew**：`brew update && brew upgrade gc`
- **pip / pipx**：`pip install -U gitcode-cli` / 在对应环境升级
- **deb / rpm**：通过系统包管理器升级
